# Custode dei Segreti — Agent Credential Protocol（通用版）

> Custode dei Segreti：意大利语，“秘密的守护者”。

> 让任何 AI Agent 都用同一种方式处理密码、API Key 和验证码：
> **模型负责“用”，保管箱负责“存”，用户负责“批”。密码原文永远不经过模型的眼睛和聊天记录。**

这不是 Muse 专属功能说明，而是一份与平台无关的通用协议。它解决的是一个很具体的问题：
每次换一个新模型/新 Agent，用户都要被重新教育一遍“不要把密码发给我”，
而模型除了说教，也给不出一条真正能干活的安全路径。

---

## 先说清：这份仓库能做什么、不能做什么

| | 说明 |
|---|---|
| ✅ 能做 | 给任何模型一份统一的行为规则：不索要明文、不存进记忆/日志/代码、不反复说教；有保管箱的平台按保管箱流程走，没有的就明确停下 |
| ✅ 能做 | 给平台/工具开发者一份保管箱（Vault）的参考规范，自己照着实现真正的隔离存储 |
| ❌ 不能做 | 一份 Markdown 本身**不会**给某个模型凭空变出保管箱。没有安全录入通道的平台，模型只能遵守“不接收明文”这一层，不能假装自己有 Vault |

## 30 秒用法（给用户）

换新模型时，二选一：

1. **把本仓库链接丢给它**，并说一句：`按这个仓库的 AGENTS.md 处理所有凭据。`
2. **把 [`paste-anywhere.md`](paste-anywhere.md) 里的短版**粘进它的系统提示词 / 自定义指令 / 项目说明里。

之后它应该做到：

- 不让你在聊天里发密码、API Key、恢复码；
- 只问“哪个站、哪个账号标签”，不问密码本身；
- 只能确认“有没有存着”，说不出、读不出、删不掉已保存的凭据（删除由用户在设置里做）；
- 每次真正登录/使用前，先经你批准（批准分级：一次 / 限时 / 某范围始终；高风险目标永远当场批，申请时它要给出理由）；
- 一次性验证码只短暂使用、用完即弃，不进记忆、不进日志；
- 只说明一次边界，然后给可执行的下一步——不反复说教，不拿“安全”为由直接拒绝干活。

## 核心模型（五句话）

1. **分离**：凭据存储与模型上下文是两个系统。模型上下文被导出、被记录、被压缩，都不该波及密码。
2. **不透明引用**：模型手里只有 `[credential:<uuid>]` 这类引用和元数据（站点 origin、标签、类型），没有原文。
3. **安全录入**：密码只能经独立的安全录入界面进入保管箱，不经过聊天、文件、环境变量或代码。
4. **批准门**：保管箱把凭据交给浏览器/工具去填的那一刻，必须有用户对“这个站、这一次”的批准。
5. **短暂性**：验证码等一次性凭据只在内存里短暂存在（参考值约 10 分钟），用完销毁，永不落盘、永不进记忆。

## 能防 / 不能防（诚实版）

| 威胁 | 防得住吗 |
|---|---|
| 密码滑进对话记录、模型记忆、日志、生成代码 | ✅ 防得住——它从没进去过 |
| 提示注入骗模型“把密码说出来” | ✅ 防得住——模型没有，就说不出来 |
| 批准错站、把凭据填进钓鱼站 | ⚠️ 部分——靠 origin 以页面为准 + 精确匹配 + 批准时展示真实 origin 缓解，仍需用户看一眼 |
| 目标网站把敏感数据回显在结果里 | ⚠️ 部分——协议要求把回显也当秘密脱敏，但源头不在保管箱控制内 |
| 填完之后密码存在于页面 DOM、被恶意脚本/被攻陷的主机读取 | ❌ 防不住——填充是受信任操作，不是保密保证 |
| 保管箱服务本身被攻陷 | ❌ 防不住——靠加密存储、独立部署与审计降低风险，不靠本协议 |

## 适配说明

- **有 Vault 的平台**（如 Muse 的 Secure Vault、1Password 类集成）：直接按 `SPEC.md` 的流程走。
- **只有密码管理器、没有集成的平台**：模型不接收明文，引导用户在浏览器/工具里由密码管理器自动填充，模型只接收“填好了”这个结果。
- **什么都没有的平台**：模型只遵守行为层——不索要、不接收、不存储明文，并如实说明自己没有安全录入通道。到此为止，不假装能安全地“帮你记着”。
